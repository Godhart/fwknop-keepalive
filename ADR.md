# Архитектурные решения

## 001 — Защищённый перенос профиля (2026-11-08)

Шифруется весь JSON v1 в контейнер v2. Используем AES-256-GCM с тегом 128 бит,
случайным nonce 12 байт и фиксированным AAD. Ключ 32 байта получается через
PBKDF2-HMAC-SHA256: 600 000 итераций, случайная соль 16 байт, пароль UTF-8
без нормализации (1..1024 байта). Параметры формата фиксированы, неподдерживаемые
значения отклоняются до дорогого KDF. Формат переносим между Python cryptography
и Android JCA API 26+. SPA-протокол libfko не меняется. Это защита файлов при
переносе, не замена шифрования SPA и не управление паролями сервера.

В bash встроены контейнер и минимальный Python-дешифратор, а не пароль или
открытые ключи. Пароль считывается только с tty без эха. После разблокировки
fwknop читает rc с правами 0600; rc удаляется при завершении и обрабатываемых
сигналах. SIGKILL/сбой ОС не позволяют гарантировать удаление. Память процесса
и временный rc во время работы доступны владельцу процесса. Цикл включается
явным --loop, пароль вводится один раз на запуск. Незашифрованный режим сохраняется.

## 002 — Несколько Android-профилей (2026-11-08)

До 16 профилей имеют независимые UUID, настройки, циклы и статусы. Один foreground
service и один wake lock обслуживают набор сессий. Пул позволяет DNS одного
сервера не блокировать другие; libfko/JNI вызовы сериализованы, чтобы не полагаться
на потокобезопасность глобального состояния C-библиотеки. Остановка сессии
отменяет таймер и запрещает дальнейшую отправку; последняя остановка завершает сервис.

Профили сохраняются одной AES-GCM-зашифрованной коллекцией под Android Keystore,
одной транзакцией SharedPreferences. Миграция переносит прежний единственный профиль
и удаляет старую запись в той же транзакции. Ошибка расшифровки не заменяет данные
пустой коллекцией. Пароль импорта не сохраняется; фоновый сервис не зависит от него.
Активность только в памяти, START_NOT_STICKY: после смерти процесса нет фиктивно
активных профилей и автоматического старта. Импорт не запускает и не заменяет сессии.
