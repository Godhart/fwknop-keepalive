# Проверки SPA Keepalive 0.2.0

В среде подготовки выполнено **47 тестов, все прошли**, включая настоящий
upstream fwknop client 2.6.11, собранный из исходников:

```bash
pip install -r tools/requirements.txt pytest
python -m pytest -q tests
# Дополнительная интеграция с установленным fwknop:
FWKNOP_TEST_BINARY="$(command -v fwknop)" python -m pytest -q tests
```

Первый вариант пропускает тест реального CLI, если переменная не задана.
Для нативных тестов нужен GCC. Они собирают из тех же C-файлов библиотеку
для хоста, создают пакет через `packet.c` и расшифровывают его через libfko.
Проверяются username, message, timeout, различие повторных пакетов,
отклонение изменённого пакета и неверного HMAC. Это не независимый аудит
криптографии: обе стороны используют upstream libfko.

Проверены: неправильные/неизвестные поля, дубли YAML, диапазоны портов,
IPv4, Base64, период, защита от добавления строки в fwknoprc, синтаксис bash,
права выходных файлов, отсутствие перезаписи, приватный временный rc и его
очистка, совпадение схемы Android и Python. Реальный CLI направлял пакет
только на 127.0.0.1; тест проверял расшифрованные поля этого пакета.
Проверена компиляция Python. Создание PNG проверено; сканирование камерой не проверялось.

**Не выполнены:** Gradle/NDK-сборка APK, инструментальные Android-тесты,
проверка камеры/Keystore/уведомлений на телефоне, проверка GUI с дисплеем,
проверка с вашим сервером/Ansible, долгий прогон в Doze и смена мобильной сети.
В окружении не было Android SDK/NDK, устройства и графического дисплея.

## Перед постоянным использованием

1. Собрать APK и проверить импорт настоящего QR на Android 8+, 13+, 14/15+.
2. Убедиться, что импорт сам по себе не отправляет пакеты.
3. После запуска проверить журнал сервера и реальный доступ к нужным портам.
4. Выключить экран минимум на 30 минут; проверить интервалы на стороне сервера.
5. Проверить Doze с исключением батареи и без него:
   `adb shell dumpsys deviceidle force-idle`, затем
   `adb shell dumpsys deviceidle unforce`.
6. Переключить Wi-Fi → мобильная сеть, проверить новый источник и старый таймаут.
7. Отключить сеть на несколько периодов и включить снова.
8. Проверить «Остановить», остановку из уведомления, замену и удаление профиля,
   перезагрузку и force-stop. После прекращения отправок доступ должен истечь
   по серверному таймауту, а не обязательно немедленно.
9. Проверить неправильный ключ и часы: успешный UDP send не должен считаться
   подтверждением доступа.
10. Проверить расход батареи; continuous partial wake lock — осознанный компромисс.

## Новые проверки 0.2.0

Проверены длины и случайность ключей, CLI new/rekey и сохранение исходного
профиля; обновление открытого vault, создание нового, сохранение комментариев,
кавычек и DNS-секретов; резервные копии и права 0600; повтор без изменений;
отклонение дублирующих полей, неверных структур, inline SPA !vault и symlink.
С настоящим ansible-vault проверены полные циклы шифрования и обновления
Vault 1.1/1.2 (с label prod), новый зашифрованный файл, неверный/отсутствующий
пароль и отсутствие изменения исходника при ошибке.

Для этих интеграционных тестов установите `tools/requirements-vault.txt`
и обеспечьте наличие `ansible-vault` в PATH; иначе они помечаются skipped.
GUI компилируется, но интерактивная проверка с дисплеем не выполнена.
