# SPA Keepalive для iOS — 0.4.0

Первый iOS-клиент, iPhone/iPad с iOS 16+. Исходники SwiftUI/UIKit; libfko 2.6.11
та же, что в Android. VPN, сервер уведомлений и фоновые разрешения не нужны.

**Статус:** в среде разработки Linux нет Xcode и iOS SDK. Здесь проверены
синтаксис Swift отдельным парсером, структура проекта, Python-совместимость
тестовых данных и сборка/расшифровка libfko-пакетов с iOS-конфигурацией на Linux.
Это не сборка приложения для iOS. Xcode-сборка, XCTest, Keychain и камера
на устройстве должны пройти проверку на Mac или в добавленном GitHub Actions.

## Возможности и поведение

- Импорт JSON через «Файлы» и QR через камеру.
- Открытый профиль v1 и защищённый v2 из Python-утилиты 0.3.0+.
- Запрос пароля для v2; AES-256-GCM, PBKDF2-HMAC-SHA256, 600 000 итераций,
  одинаковые AAD, соль, nonce и UTF-8-пароль. Сервер и Python менять не нужно.
- До 16 профилей с независимыми UUID, кнопками отправки, таймерами и удалением.
- Профили и локальные адреса сайтов сохраняются в Keychain, доступны только
  при разблокированном устройстве, не синхронизируются через iCloud и не
  переносятся на другое устройство (WhenUnlockedThisDeviceOnly).
- Пароль экспорта не сохраняется; при следующей отправке ввод не требуется.
  Это защита импорта и хранения, а не отдельный пароль на вход в приложение.
- Один свежий пакет на каждую попытку, IPv4/UDP, новые DNS-запросы через новую
  NWConnection; таймаут попытки 15 секунд. Факт отправки не подтверждает fwknopd.
- Повторение возможно только пока приложение активно. Уход в браузер,
  блокировка, открытие системного диалога или другая потеря активности останавливают
  все циклы и незавершённые отправки. Уже переданный пакет отозвать невозможно.
  После возвращения нажмите «Повторять, пока открыто» снова.
- Кнопка «SPA → открыть сайт» отправляет пакет и через 0,8 секунды открывает
  заданный HTTPS URL. Это удобная задержка, не подтверждение авторизации.
  Если сервер не успел обработать SPA, обновите страницу. При ошибке отправки
  сайт автоматически не открывается.
- URL задаётся отдельно на iPhone: он не добавляется в общий формат QR.
  Разрешены только HTTPS URL без встроенного логина/пароля.
- Приложение не меняет срок доступа сервера, не препятствует блокировке экрана
  и не обещает поддержание доступа после сворачивания.

При нескольких профилях с одинаковыми именами ориентируйтесь на короткий ID.
Удаление одного не останавливает остальные. Передача профиля сама по себе
не отправляет пакет. Удаляйте профиль кнопкой внутри приложения: Keychain
может сохранять записи после удаления и повторной установки приложения.

## Подготовка QR/JSON на Ubuntu 24.04

Используйте существующий профиль с ключами, которые уже настроены на сервере:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r tools/requirements.txt
python tools/spa_config.py generate phone.yaml --out iphone-export --protect
```

Пароль запрашивается дважды. QR в iphone-export/profile-qr.png можно отсканировать
с экрана компьютера. Для импорта файла передайте profile.json доверенным способом
в приложение «Файлы» на iPhone. Старые открытые QR/JSON тоже работают.
Ключи тестовых Fixtures публичные и предназначены только для тестов.

## Сборка через GitHub Actions с Ubuntu

1. Перенесите изменения в репозиторий. Нужен весь проект, включая общий
   android/app/src/main/cpp/vendor и profile.schema.json; одной папки ios мало.
2. Отправьте коммит в GitHub.
3. Откройте Actions → iOS → Run workflow (или дождитесь автоматического запуска).
4. Workflow на macos-15 установит XcodeGen, создаст проект, запустит XCTest
   на доступном iPhone Simulator и скомпилирует вариант для физического iPhone.
5. Скачайте ios-test-results для отчёта; spa-keepalive-ios-simulator содержит
   приложение только для симулятора на Mac.

**Артефакт симулятора нельзя установить на iPhone.** Сборка для устройства в CI
выполняется без подписи и проверяет компиляцию. Для установки нужен сертификат
подписи и provisioning profile вашего Apple Account. В workflow не добавлены
чужие ключи, платная учётная запись или автоматическая публикация.

На Ubuntu можно редактировать исходники и запускать workflow, но локально
собрать и запустить этот проект штатным Xcode нельзя: нужен macOS/Xcode.
Первую установку проще сделать через Mac по инструкции ниже.

## Сборка и установка на собственный iPhone через Mac

1. Установите Xcode из Mac App Store. Нужен Xcode 16 или новее с SDK,
   поддерживающим установленную на вашем iPhone версию iOS. Запустите Xcode,
   примите лицензию, установите предлагаемые iOS-компоненты.
2. В Xcode → Settings → Accounts добавьте свой Apple Account.
3. Установите XcodeGen (при наличии Homebrew):

   ```bash
   brew install xcodegen
   ```

   Альтернативные способы: https://github.com/yonaskolb/XcodeGen#installing

4. Распакуйте весь архив или клонируйте репозиторий. Выполните:

   ```bash
   cd fwknop-keepalive/ios
   xcodegen generate
   open SpaKeepalive.xcodeproj
   ```

   После распаковки архива имя корневого каталога может содержать версию.
   project.yml — основной источник настроек проекта. После его изменения
   повторите xcodegen generate.

5. В Xcode выберите target SpaKeepalive → Signing & Capabilities:
   включите Automatically manage signing, выберите свою Team.
   Замените Bundle Identifier на уникальный, например com.yourname.spakeepalive.
   Чтобы сохранить настройку при повторной генерации, внесите идентификатор
   в ios/project.yml (PRODUCT_BUNDLE_IDENTIFIER); при желании добавьте там
   DEVELOPMENT_TEAM с вашим Team ID. Секретных ключей в YAML быть не должно.
6. Подключите iPhone кабелем, подтвердите доверие к компьютеру. При запросе
   включите Settings → Privacy & Security → Developer Mode и перезагрузите
   телефон. Следуйте подсказкам Xcode по доверию сертификату.
7. Выберите схему SpaKeepalive и свой iPhone как устройство запуска.
8. Нажмите Run (Cmd+R). Xcode соберёт, подпишет и установит приложение.
9. Для первого теста импортируйте QR/JSON, проверьте сервер/порты, подтвердите
   добавление и нажмите «Отправить SPA». Сверьте журнал fwknopd и доступ.
10. Укажите сайт в карточке профиля и проверьте «SPA → открыть сайт».

Для личной проверки доступен бесплатный Personal Team. Его provisioning profiles
действуют 7 дней: понадобится повторная сборка/установка через Xcode. Для TestFlight
и обычного распространения нужен соответствующий Apple Developer Program workflow.
При обновлении сохраняйте Bundle Identifier и Team, чтобы пользоваться тем же
контейнером/Keychain. Сохраните исходный защищённый экспорт на случай переустановки.

Официальные инструкции:
- https://developer.apple.com/help/account/basics/about-your-developer-account
- https://help.apple.com/xcode/mac/current/en.lproj/dev5a825a1ca.html
- https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device

## Тесты и ручная проверка

На Mac:

```bash
cd ios
xcodegen generate
xcrun simctl list devices available
# Подставьте ID одного из доступных iPhone Simulator:
xcodebuild -project SpaKeepalive.xcodeproj -scheme SpaKeepalive \
  -destination 'platform=iOS Simulator,id=SIMULATOR-UUID' test
```

XCTest проверяет:
- расшифровку fixture, созданного Python, с кириллицей и emoji в пароле;
- неверный пароль, изменённый ciphertext и недопустимое число итераций;
- дубли JSON, неизвестные поля, неправильные ключи/порты/IP/периоды;
- создание разных SPA-пакетов при повторных попытках;
- независимость двух профилей, остановку всех при потере активности,
  отсутствие автоперезапуска и сохранение через подставленное тестовое хранилище;
- отсутствие записи при ошибке чтения хранилища, лимит 16, проверку URL.

Тест хранилища модели использует подстановку, **не настоящий Keychain**.
Тест жизненного цикла создаёт сетевые попытки только на 127.0.0.1.

На настоящем iPhone отдельно проверьте:
1. Камеру, отказ в разрешении камеры, импорт JSON через «Файлы».
2. Пароль правильный/неправильный, отмену и подтверждение импорта.
3. Сохранение профилей после закрытия и повторного запуска приложения.
4. Две отправки на реальные серверы и независимые циклы при открытом приложении.
5. Остановку при блокировке, уходе в Safari и возврате. Автоматического
   возобновления не должно быть.
6. Поведение при отсутствии сети, смене Wi-Fi на мобильную сеть, неверном ключе.
7. Истечение серверного доступа после остановки отправок.

Не используйте отсутствие ошибки UDP как проверку того, что доступ разрешён:
в этой версии нет ответа сервера на SPA.
