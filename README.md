# SPA Keepalive 0.4.0

Простой набор для периодической отправки fwknop SPA: Android-приложение,
Python-конфигуратор с YAML/JSON Schema и QR, необязательный GUI CustomTkinter,
генератор автономного bash-скрипта с параметрами внутри.

Версия 0.3.0 добавляет защищённый паролем экспорт и несколько одновременно
работающих Android-профилей. Предыдущая версия 0.2.1 проверена владельцем на
телефоне: длительная работа в фоне стабильна, заметного влияния на батарею
не обнаружено. Проверки текущей версии описаны в [TESTING.md](TESTING.md).

## iPhone и iPad

В 0.4.0 добавлен iOS-клиент: импорт общих JSON/QR с паролем, Keychain,
несколько профилей, ручная отправка и «SPA → открыть сайт». Повторение — только
пока приложение активно; после сворачивания циклы останавливаются.
[Подробная инструкция iOS: сборка, подпись, установка и проверки](ios/README.md).
Добавлен отдельный GitHub Actions workflow iOS для сборки и XCTest на macOS.
Локально в среде подготовки Xcode-сборка не выполнялась.

Ниже описаны существующие Android-клиент и Python/bash-инструменты.

## Вводная информация

Приложение не требует root, не создаёт VPN и не запускает shell-команды.
Каждая отправка создаёт новый пакет штатной libfko 2.6.11 через JNI:
AES-CBC, SHA256 digest, обязательный отдельный HMAC-SHA256.
Поддерживаются IPv4, UDP, до 16 профилей одновременно, запросы доступа к TCP/UDP-портам
с явно заданным сроком. NAT-команды fwknop, GPG, IPv6, HTTP/TCP-транспорт SPA
и выполнение команд на сервере не поддерживаются.

На Android используется foreground service типа `specialUse`, постоянное
уведомление с кнопкой остановки и partial wake lock на время работы.
Период — пауза **после завершения попытки**, а не жёсткое расписание.
При ошибке отправка повторяется через тот же период. После успешного запуска
первый пакет отправляется сразу; DNS сервера разрешается заново при каждой попытке.
Ни Android, ни UDP не гарантируют доставку и непрерывный доступ.

Для выключенного экрана отключите оптимизацию батареи для приложения и
ограничения фоновой работы производителя. Wake lock расходует заряд.
При Doze без исключения возможны длительные задержки даже с foreground service.
После перезагрузки, force-stop, остановки системой или выгрузки процесса
нужно снова нажать «Запустить»; скрытого автозапуска нет.
Это приложение для самостоятельной установки; публикация в Google Play
потребует отдельного обоснования и проверки `specialUse`.

## Быстрый старт: Python

Python 3.10+; для bash — Linux, bash, coreutils, util-linux и fwknop-client.
Все операции генерации выполняются локально, QR-сервисы не используются.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r tools/requirements.txt
cp profile.example.yaml my-server.yaml
chmod 600 my-server.yaml
```

Отредактируйте `my-server.yaml`: адрес сервера, порты, username, срок доступа,
период и **существующие** `KEY_BASE64` / `HMAC_KEY_BASE64` из нужной записи сервера.
В примере намеренно стоят невалидные placeholders, а не рабочие общие ключи.

Для нового устройства, которому вы собираетесь выдать отдельные ключи:

```bash
python tools/spa_config.py new new-device.yaml
```

Команда создаёт два новых случайных 32-байтных ключа в файле с правами 0600.
Она **не обновляет сервер**. Ключи можно перенести в локальный vault командой
`update-vault`, затем самостоятельно применить Ansible playbook, как описано ниже.
После настройки:

```bash
python tools/spa_config.py validate my-server.yaml
python tools/spa_config.py generate my-server.yaml --out my-server-export
```

Будет создан новый каталог с правами 0700:

| Файл | Назначение |
|---|---|
| `profile-qr.png` | Сканируется Android-приложением |
| `profile.json` | Полный профиль, содержимое QR |
| `keepalive.sh` | Bash с параметрами внутри; один пакет или цикл `--loop`, права 0700 |

Повторная генерация в существующий каталог запрещена, чтобы случайно не
перезаписать ключи. Укажите новое имя каталога.
Без `--protect` QR/JSON/bash содержат открытые ключи.

### Экспорт с паролем

```bash
python tools/spa_config.py generate my-server.yaml --out protected-export --protect
```

Утилита дважды запросит пароль без отображения ввода. JSON, QR и bash содержат
одинаковый **зашифрованный профиль целиком**, включая ключи и адрес сервера.
Пароль в файлы не записывается и не передаётся аргументом или переменной окружения.
Используются AES-256-GCM и PBKDF2-HMAC-SHA256 (600 000 итераций), случайные соль
и nonce для каждого экспорта. Подмена данных и неверный пароль отклоняются.
Описание контейнера: [encrypted-profile.schema.json](encrypted-profile.schema.json).

Исходный YAML остаётся открытым. Команды `new` и `rekey` также создают открытый
YAML; права файла — 0600. Пароль защищает экспортированные файлы, а не редактор,
работающий процесс или исходник. Выбирайте длинный уникальный пароль: получивший
файл может пробовать пароли автономно. Восстановления забытого пароля нет.

Старые незашифрованные профили версии 1 поддерживаются; зашифрованный формат
версии 2 требует приложения 0.3.0+. Версия внутреннего профиля остаётся 1.
Для смены пароля повторите экспорт с `--protect` в новый каталог; сами SPA-ключи
и сервер менять не требуется. Предыдущие копии продолжают открываться старым паролем.

Команды `validate`, `generate`, `rekey`, `update-vault` принимают защищённый
JSON и запрашивают пароль для чтения. Для защиты результата `generate` нужно
снова указать `--protect`. Пароль профиля и пароль Ansible Vault независимы.

## Параметры

Полные описания находятся в [profile.schema.json](profile.schema.json).
Неизвестные поля, повторные YAML-поля, неправильные ключи, IP и порты отклоняются.
Дополнительные проверки Base64 и соотношения периода/таймаута выполняет утилита;
одной JSON Schema для них недостаточно.

| Поле | Смысл / пример |
|---|---|
| `version` | Версия формата QR: `1` |
| `name` | Отображаемое имя профиля |
| `server`, `spa_port` | Куда отправить SPA, например `spa.example.org`, `62201` |
| `access` | Какие порты разрешить: `tcp/22,tcp/443` |
| `allow_ip` | `source` либо конкретный IPv4 клиента после NAT |
| `username` | Имя в SPA: например `mobile`; учитывает `REQUIRE_USERNAME` сервера |
| `interval_seconds` | 15..86400; например `60` |
| `access_timeout_seconds` | 30..86400; например `300`; должен превышать период |
| `key_base64` | KEY_BASE64 сервера, 16..32 декодированных байта |
| `hmac_key_base64` | HMAC_KEY_BASE64 сервера, 32..64 байта, отдельный ключ |

Рекомендуется запас минимум в три периода. Сервер может ограничивать срок
через `MAX_FW_TIMEOUT`; фактическое время доступа определяет именно сервер.
Профиль не даёт разрешений сверх серверной политики.

### Адрес клиента и мобильная сеть

`source` помещает `0.0.0.0` в SPA-сообщение: fwknopd использует адрес источника
полученного пакета. Необходимо `REQUIRE_SOURCE_ADDRESS N` в соответствующей
серверной записи. Это удобно при NAT и смене сети и не требует внешнего сервиса
определения IP. HMAC при этом остаётся обязательным.

Если сервер требует `REQUIRE_SOURCE_ADDRESS Y`, укажите в `allow_ip` реальный
внешний IPv4 клиента. При смене адреса такой профиль потребуется обновить.

SPA и соединение с защищённым сайтом должны выходить через один внешний IP.
Другой VPN, прокси браузера, разные маршруты или обращение к сайту по IPv6
могут привести к несовпадению. SPA сам по себе не переключает маршруты.
При смене сети старый адрес может оставаться разрешённым до серверного таймаута:
этот клиент не реализует принудительное «только один IP на ключ».

## GUI CustomTkinter

```bash
# Ubuntu, если Tk ещё не установлен:
sudo apt install python3-tk
pip install -r tools/requirements-gui.txt
python tools/spa_gui.py
```

GUI — редактор YAML с новым профилем, выбором длины ключей, их заменой,
сохранением, проверкой, созданием QR/JSON/bash и обновлением vault.
При запуске в редакторе сразу создаётся новый профиль с двумя случайными
32-байтными ключами; на диск он записывается только через «Сохранить как». Генератор тот же, что в CLI. Для защищённого экспорта включите «Шифровать JSON, QR и bash паролем»: появится двойной запрос пароля. Кнопка экспорта создаёт
под выбранным каталогом новый `spa-export`. Ключи видны в редакторе;
не показывайте его при демонстрации экрана. «Открыть» распознаёт защищённый JSON и спрашивает пароль. «Сохранить YAML» сохраняет открытый текст редактора; переключатель шифрования относится только к экспорту.

## Генерация и смена ключей

В 0.1.0 команда `new` уже создавала ключи автоматически. В 0.2.0 появились
настраиваемые длины, команда `rekey` и соответствующие кнопки GUI.
Источник — `secrets.token_bytes`, криптографический генератор ОС; seed,
парольные фразы и повторяемая генерация не предусмотрены.

```bash
# Значения по умолчанию — 32 / 32; подходят текущему Ansible-проекту.
python tools/spa_config.py new phone.yaml --key-bytes 32 --hmac-key-bytes 32

# Заменить ключи, сохранив сервер, порты и остальные поля; исходник не меняется.
python tools/spa_config.py rekey phone.yaml --out phone-rotated.yaml \
  --key-bytes 32 --hmac-key-bytes 32
```

| Параметр | Допустимые значения | По умолчанию |
|---|---|---|
| `--key-bytes` | 16..32 случайных байта секрета до Base64 | 32 |
| `--hmac-key-bytes` | 32..64 случайных байта до Base64 | 32 |

Это длина входных секретов libfko, **не выбор AES-128 / AES-256**.
Алгоритмы SPA остаются AES-CBC и HMAC-SHA256.
`generate` и `update-vault` никогда не создают новые ключи: используют именно
значения текущего профиля. Это предотвращает рассинхронизацию QR и сервера.
Для `new`, `rekey`, `generate` целевой файл/каталог должен быть новым.

## Обновление vault.yaml / vault.yml

Интеграция сверена с **fwknop-spa-ansible 0.7.1**:

| Профиль клиента | Переменная серверного vault |
|---|---|
| `key_base64` | `spa_key_base64` |
| `hmac_key_base64` | `spa_hmac_key_base64` |

Оба ключа для этого серверного проекта должны быть **ровно 32 байта**.
Если сгенерированы другие длины, команда отклонит обновление до записи.
Это ограничение серверной схемы; оно не сужает допустимые длины обычного профиля.
В текущем серверном проекте пара ключей глобальная, а не список клиентов:
замена повлияет на все устройства, использующие прежнюю пару.

Для открытого YAML:

```bash
python tools/spa_config.py update-vault phone.yaml \
  --vault ../fwknop-spa-ansible/group_vars/all/vault.yaml
```

Название может быть и `vault.yml` — используйте **существующий файл проекта**.
Не создавайте рядом второй файл с другим расширением и дублирующими переменными.
Чтобы создать отсутствующий файл, добавьте `--create` (родительский каталог
должен существовать). Для шифрования нового или открытого файла добавьте `--encrypt`.

Для зашифрованного Ansible Vault установите дополнительную зависимость:

```bash
pip install -r tools/requirements-vault.txt

python tools/spa_config.py update-vault phone.yaml \
  --vault ../fwknop-spa-ansible/group_vars/all/vault.yml \
  --vault-password-file ~/.config/ansible/spa-vault-password
```

Файл пароля должен содержать пароль **Ansible Vault**, а не SPA-ключ.
Создайте его в доверенном каталоге и задайте `chmod 600`. Он не включается
в QR, профиль или bash. Для Ansible Vault утилита не спрашивает пароль интерактивно и не принимает
сам пароль аргументом; используется официальный `ansible-vault`.

Создать сразу зашифрованный файл:

```bash
python tools/spa_config.py update-vault phone.yaml \
  --vault ../fwknop-spa-ansible/group_vars/all/vault.yml \
  --create --encrypt \
  --vault-password-file ~/.config/ansible/spa-vault-password
```

Поведение:

- Изменяются только два поля SPA. Остальные данные, в том числе
  `spa_acme_dns_credentials`, сохраняются; ruamel.yaml сохраняет комментарии,
  порядок и кавычки, хотя форматирование YAML может немного измениться.
- Зашифрованный файл всегда повторно шифруется. Поддерживаются целые файлы
  Ansible Vault 1.1/1.2 AES256, включая сохранение vault-id label.
  Расшифрованный YAML передаётся в памяти через stdin/stdout и не записывается
  во временный plaintext-файл. Это не защищает от swap или дампа памяти ОС.
- Открытый файл остаётся открытым, если не задан `--encrypt`.
- Перед изменением создаётся точная резервная копия `vault.yml.bak-<id>`, права
  0600. Она содержит старые ключи; храните её приватно. Если исходник открыт,
  **резервная копия тоже открыта**, даже при добавлении `--encrypt`.
- Запись выполняется через временный файл и атомарную замену, с правами 0600.
  Совпадающие ключи не приводят к переписыванию или новой резервной копии.
- Неправильный пароль, дубли YAML, неверный формат и несовместимая длина ключей
  прекращают операцию до изменения исходника. Диагностика не выводит ключи
  или содержимое расшифрованного vault.
- Inline `!vault` непосредственно в одном из двух SPA-полей не заменяется
  открытым секретом: для этой операции используйте шифрование всего файла.
  Посторонние поля `!vault` сохраняются. Корневой YAML merge (`<<`) отклоняется.
- Используйте доверенный локальный каталог. Одновременные операции этой утилиты
  блокируются файлом `.spa-update.lock`; изменения другим редактором также
  проверяются перед заменой. Не редактируйте файл параллельно. После аварии
  удаляйте оставшийся lock только убедившись, что процесс уже не работает.

В GUI кнопка «Обновить vault.yaml» использует ключи **из редактора**. Для
зашифрованного файла будет предложено выбрать файл пароля; переключатель
«Шифровать открытый / новый vault» включает шифрование при первой записи.
Изменения профиля нужно отдельно сохранить через «Сохранить как».

### Последовательность обновления сервера

1. Создайте/отредактируйте профиль или выполните `rekey` в новый файл.
2. Выполните `update-vault` для фактического vault вашего Ansible-проекта.
3. Из каталога серверного проекта запустите его обычное развёртывание:

   ```bash
   ansible-playbook -i inventory/hosts.yml playbook.yml --ask-vault-pass --ask-become-pass
   ```

4. Выпустите новый комплект клиента и импортируйте QR на телефон:

   ```bash
   python tools/spa_config.py generate phone-rotated.yaml --out phone-rotated-export
   ```

5. Запустите новый профиль и проверьте серверный журнал и доступ.

Утилита **не подключается к серверу и не запускает Ansible playbook**.
Смена ключей не выполняется транзакционно между сервером и устройствами:
заранее сохраните административный доступ на время переключения.
При глобальной смене ключей обновите все использующие их клиенты.

## Сборка и установка Android

Минимум Android 8.0 / API 26. Проект рассчитан на API 35, JDK 17,
Gradle 8.11.1, Android Gradle Plugin 8.9.2, NDK 28.0.13004108,
CMake 3.22.1. ABI: arm64-v8a, armeabi-v7a, x86_64.
libfko включена исходниками; загрузка её с сети при сборке не нужна.
Gradle, Android SDK и Maven-зависимости при первой сборке требуют интернет.

1. Откройте каталог `android` в Android Studio с поддержкой AGP 8.9.2.
2. В SDK Manager установите Android SDK Platform 35, NDK и CMake указанных версий.
3. Дождитесь синхронизации Gradle, затем Build → Build APK(s).

Или из терминала при настроенном SDK:

```bash
cd android
# При необходимости укажите sdk.dir=/absolute/path/to/Android/Sdk в local.properties.
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Debug APK предназначен для проверки. Для постоянной установки соберите
подписанный release APK через Android Studio → Generate Signed Bundle / APK.
Сохраните собственный ключ подписи для будущих обновлений.

На телефоне:

1. Откройте SPA Keepalive и нажмите «Импортировать QR» или «Импортировать JSON».
2. Разрешите камеру, наведите на `profile-qr.png`, проверьте сервер и порты,
   подтвердите импорт. Для зашифрованного профиля сначала введите пароль. Сам импорт ничего не отправляет.
3. Откройте «Настройки батареи», найдите приложение и отключите оптимизацию.
   При необходимости разрешите фоновую работу в настройках производителя.
4. Нажмите «Запустить» у нужного профиля. На Android 13+ разрешите уведомления и повторите запуск.
5. Проверьте журналы fwknopd и доступ к защищённому сервису.
6. «Остановить» выключает выбранный профиль, «Остановить все» в приложении или уведомлении — все.

Каждый импорт добавляет отдельный профиль с собственным идентификатором.
Одинаковые имена допустимы: рядом показывается короткий ID. До 16 профилей
можно запускать одновременно; у каждого свой сервер, ключи, период и статус.
Импорт, остановка или удаление одного профиля не останавливают другие.
Период каждого отсчитывается после завершения его попытки. Ошибка одного
сервера не прекращает остальные циклы.

Пароль требуется **только при импорте**, затем профиль хранится локально
зашифрованным ключом Android Keystore. Пароль не сохраняется; повторный запуск
профиля не требует его ввода, чтобы фоновая работа оставалась независимой.
Это не блокировка приложения паролем. Резервное копирование отключено.
Приложение блокирует снимки своего экрана.

При обновлении поверх старой версии с той же подписью прежний профиль
автоматически переносится в список. Перед обновлением остановите сервис;
после обновления запустите нужные профили вручную. Удаление приложения стирает
профили: сохраните исходники/экспорты отдельно. Debug APK из другого CI-запуска
может иметь другую подпись; при ошибке несовпадения подписей обновление поверх
установленного APK невозможно без исходного ключа подписи.

## Bash-цикл с теми же настройками

```bash
sudo apt install fwknop-client coreutils util-linux
./my-server-export/keepalive.sh          # один пакет (новое поведение по умолчанию)
./my-server-export/keepalive.sh --once   # явно один пакет
./my-server-export/keepalive.sh --loop   # повторять с периодом из профиля
# Ctrl+C завершает цикл.
```

Защищённый скрипт запрашивает пароль при каждом запуске, один раз на весь цикл.
На Ubuntu 24.04 ему дополнительно нужны `sudo apt install python3 python3-cryptography`
либо активное Python-окружение с `cryptography`. Других файлов проекта рядом
не требуется. Без интерактивного терминала защищённый скрипт отказывает в запуске.
Неверный пароль прекращает работу до вызова fwknop.
Открытый скрипт не требует Python и пароля. `--help` показывает доступные опции.

Скрипт создаёт приватный временный fwknoprc (0600), передаёт CLI только его
путь и удаляет каталог при штатном завершении/сигнале. Ключи не передаются
аргументами процесса. Каждый вызов ограничен 20 секундами плюс 2 секундами
на принудительное завершение, затем цикл выдерживает указанный период.
`--once` возвращает код ошибки CLI/timeout. Ошибка в бесконечном режиме
не прекращает дальнейшие попытки. Вывод CLI скрыт, чтобы не утекли секреты;
скрипт выводит только общий результат. `flock` предотвращает одновременный
запуск одного файла; копии с другим inode этим не блокируются.

Параметры полностью встроены: исходные YAML/JSON рядом не нужны.
Нужен установленный `fwknop`; скрипт не содержит бинарник клиента.
При SIGKILL/аварии временный каталог может остаться, а trap не выполнится.
Не запускайте с `bash -x`: трассировка может раскрыть конфигурацию.

## Согласование с сервером

Пример записи **для адаптации**, не готовый патч вашего Ansible-проекта:

```text
SOURCE                  ANY
KEY_BASE64              <тот же key_base64>
HMAC_KEY_BASE64         <тот же hmac_key_base64>
HMAC_DIGEST_TYPE        SHA256
REQUIRE_USERNAME       mobile
REQUIRE_SOURCE_ADDRESS N
OPEN_PORTS             tcp/22,tcp/443
FW_ACCESS_TIMEOUT      300
MAX_FW_TIMEOUT         300
```

Сверьте `PCAP_FILTER`, интерфейс захвата и UDP-порт SPA с конфигурацией
fwknopd. Открывать обычный UDP-сервис на порту SPA не требуется: fwknopd
захватывает пакет. Если работает доступ через nftables/ipset или дополнительные
хуки, сохраните существующую серверную логику. Этот архив сервер не меняет.

Для телефона и компьютера лучше выдавать разные ключи и отдельные профили:
так их можно отзывать независимо. Генератор по запросу может создать QR и
bash с одинаковыми параметрами, но это не делает устройства независимыми.

## Диагностика

- «UDP отправлен» означает только успешный локальный `send`, не принятие сервером.
- Нет доступа: проверьте ключи, HMAC, username, часы телефона/сервера, разрешённые
  порты, адрес источника, IPv4/IPv6 и журнал fwknopd.
- Доступ пропадает при выключенном экране: проверьте исключение Doze,
  ограничения производителя, серверный таймаут; увеличьте запас по времени.
- Force-stop или остановка foreground service системой: откройте приложение
  и запустите вручную. История последнего события не является признаком
  работающего сервиса; ориентируйтесь на системное уведомление.
- Собранный пакет постоянно отклоняется: сначала проверьте `--once` на Linux,
  затем серверные ограничения. Не публикуйте пакет/ключи в открытых логах.
